# Treksor on Apple Watch

The watch opens to the latest published Power Thought, with its editorial date. It fetches the public dashboard feed directly and keeps a dated copy for offline reading. A second view shows three optional seven-day totals from the paired iPhone: finished gym sessions, recorded sets and timed practice minutes. Progress sharing is off by default. Enable it in **Progress → Your connected life**. The watch sends a read-only request each time the progress view opens. It clears the response when the app backgrounds, the view closes or the connection drops.

Power Thought alerts are a separate opt-in on iPhone. Apple routes notifications to the iPhone or the unlocked paired watch based on settings and device state. Treksor provides a native notification view using its original mark, system type and Architect palette. A signed iPhone and watch build with working APNs credentials is required for end-to-end delivery verification.

## Gym on the watch — feature branch (not yet released)

The new **Gym workout** view complements Power Thoughts and Progress. Begin a session on the iPhone, then open Gym on the paired Apple Watch. The screen presents one exercise at a time, its prescribed sets and reps, previous weight, large kg/reps controls, a local elapsed stopwatch, and an optional **Watch technique** action. Tapping the video control requests a fresh, time-limited signed media URL from the connected iPhone; clips never autoplay while browsing exercises. Audio starts muted, and leaving the page stops playback. A live iPhone connection and network access are needed for videos and saving sets, but the stopwatch itself is local.

Saving a set uses the active session and a deterministic set ID, so retries cannot double-count the same set. A changed or missing workout refuses stale operations. The iPhone remains the authority for saved progress and the rest deadline. Gym sharing has a **separate, initially off** toggle in **Progress → Your connected life**, and can be revoked without affecting the existing watch-progress permission. No new Apple Health authorization, cloud table or background recording is introduced.

**Native validation required:** this branch changes watchOS SwiftUI source and the iPhone-side WatchConnectivity module's video-request timeout. It needs a signed watch+iPhone development build and real-device testing; refreshing Expo JavaScript alone cannot install a changed watch UI. Apple recommends short exercise clips (ideally ≤30 s) encoded for watchOS, so existing full-size MP4s may require a separate video encoding pipeline before production playback is reliable. The current watch media API uses the existing signed iPhone catalog URL and does not claim transcoding or offline downloads. Do not merge, deploy or reinstall without approval.
